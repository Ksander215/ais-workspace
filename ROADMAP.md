# Дорожная карта AIS — Autonomous Intelligent System

Документ описывает стратегический план развития AIS. Приоритеты корректируются по результатам
внешней валидации, а не по внутренним ощущениям.

---

## Текущий фокус — внешняя валидация

AIS не расширяет архитектуру до тех пор, пока внешние данные этого не требуют. Базовый контур
проверяется на замороженном корпусе реальных open-source репозиториев (Polygon / Technical
Validation Ground) вопросами Q1–Q7 по архитектуре, модулям, зависимостям, оркестрации,
evidence против inference, границам определения и актуальности данных.

**Правила прохода:** факт ≠ гипотеза; отсутствие ответа ≠ подтверждение; CI ≠ runtime;
демо ≠ ценность; результаты не выдумываются; состав корпуса не меняется из-за плохих результатов.

## Этапы

| Этап | Фокус | Статус |
|---|---|---|
| Фундамент | Execution engine, evidence loop, interaction layer, когнитивный рантайм | ✅ |
| MVP UI | Импорт репозитория, вопросы об архитектуре, источники file:line | ✅ |
| Path security | Платформенная (POSIX/Windows) защита путей, обход traversal | ✅ |
| Импорт по commit | Закреплённый SHA, лимиты репозитория, ошибки `INVALID_REF` / `REF_NOT_FOUND` | ✅ |
| Честность claims | Разделение `scan-fact` / `lexical-match`, блок «что это за ответ и чем не является» | ✅ |
| Полигон P1 | Полный прогон Q1–Q7 на deepseek-harness + независимая сверка | ✅ |
| Полигон P2–P5 | OpenHands, Letta, Mem0, Kubernetes (non-agent contrast) | 🔄 |
| Реальный inference | Разделение fact/inference на живых прогонах с моделью | ⏳ |
| Human validation | Независимая оценка человеком по протоколу release-readiness | ⏳ |

## Что дальше

1. Закрыть P1–P5 на замороженном корпусе: BUILD / DEFER / REJECT по каждому target.
2. Проверить разделение fact/inference с реальным ключом модели.
3. Провести независимую human validation.
4. Расширять архитектуру только по фактам, зафиксированным в этих прогонах.
